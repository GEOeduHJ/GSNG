# 교과서 실제 자료 출처와 갱신 방안

작성: 2026-11-27 · 기준 커밋: `ef9379c`

이 문서는 웹 교과서 v2(13개 중단원, 절 41개)에 쓰인 실제 자료가 어디서 왔는지 정리하고, 계속 최신화해야 할 자료를 어떤 방식으로 갱신할지, 어디까지 자동화할 수 있는지를 제안한다.

- 파일별 세부 기록(제목, 원 URL, 조회일, 이용 조건, 생성 스크립트, 단위, 기준 연도)은 이미 다음 파일에 있다.
  - `content/data-manifest.yaml`(01-01)
  - `content/manifests/<중단원>.yaml`
- 출처별 검증 기록과 이용 근거는 `content/sources.yaml`과 `content/sources/<중단원>.yaml`에 있다.
- 자료별 선정 이유와 원사이트 대조표는 `scripts/data/<중단원>/README.md`에 있다.
- 이 문서는 위 기록을 출처 계열별로 묶어 갱신 관점에서 다시 본 것이다.

> 표기 구분: **[기록]**은 저장소 manifest·스크립트에서 확인한 사실이다. **[판단]**은 갱신 설계에 대한 에이전트의 제안이다. "일반적 공개 주기"는 각 기관의 관행을 요약한 것이므로, 갱신할 때마다 원 사이트에서 다시 확인해야 한다.

## 3. 갱신할 때 실제로 바뀌는 것 [기록 + 판단]

자료를 다시 받는 일 자체는 대부분 스크립트 재실행으로 끝난다. 실제 부담은 **자료에 맞춰 써 둔 글**에 있다.

1. **절 본문 숫자**
   - 41개 절 본문에 숫자가 약 464개 있다.
   - 예: "대한민국은 1960년 6.0명에서 2024년 0.7명으로 낮아졌다"(03-01 2절).
   - 자료 연도가 바뀌면 문장의 수치·연도·순위·추세 표현을 다시 써야 한다.
2. **캡션과 대체 텍스트**
   - 절 머리말(YAML)의 `caption`·`alt`에 기준 연도가 들어 있다.
   - 예: "대한민국 인구 피라미드, 2024년 추계".
3. **파일 이름**
   - 자료 파일 26개는 이름에 연도가 있다.
   - 이름을 바꾸면 절 머리말의 `data:` 경로와 manifest의 `path`도 함께 고쳐야 한다.
4. **manifest와 출처 기록**
   - `summary`에도 대표 수치가 적혀 있다.
   - `retrievedAt`, `year`, `checkedAt`, `verificationStatus`를 새로 써야 한다.
5. **교사용 안내(`teacher.md`)와 중단원 마무리 활동**
   - 수치를 인용한 발문이 있으면 함께 고친다.
6. **해석이 바뀌는 경우**
   - 순위가 뒤집히거나 추세가 꺾이면 문장 하나가 아니라 절의 설명 흐름이 바뀐다.
   - 예: 상위 생산국 순서, 분쟁 사망자 증감.
7. **이용 조건**
   - Pew(조건부 재사용), GISCO(비상업 이용), 사가르마타 보고서(발행처 표기)처럼 조건이 붙은 자료는 갱신 때마다 조건을 다시 확인한다.

## 4. 자동화 가능성 [판단]

| 단계 | 할 일 | 자동화 | 이유 |
| --- | --- | --- | --- |
| ① 새 자료 감지 | 출처마다 최신 연도·판 번호를 조회해 현재 manifest의 `year`와 비교 | **완전 자동 가능** | 조회 방법이 출처마다 정해져 있다. WDI API의 지표별 최신 비결측 연도, UCDP·NOAA·WPP의 다음 판 URL 존재 여부, UNHCR API의 연도, FAOSTAT 일괄 파일의 갱신일 등이다. 파일을 바꾸지 않고 보고서만 만든다. |
| ② 자료 재수집 | 연도 상수를 올리고 스크립트를 다시 실행해 JSON 생성 | **대부분 자동 가능(29개 스크립트)** | 다만 판 번호가 URL에 박힌 자료(WPP·UCDP·NOAA·Census)는 새 URL을 확인해야 한다. 원 자료의 열 이름이나 형식이 바뀌면 스크립트가 멈추도록 이미 검사가 들어 있다. |
| ③ 구조·수치 대조 | `check:book`, 테스트, 본문 숫자와 자료 값 대조 | **완전 자동 가능** | 새 자료와 맞지 않게 된 본문 문장 목록을 자동으로 뽑을 수 있다. 현재 작업용 대조 스크립트(`numbers.mjs`, `style-guard.mjs`)를 저장소 명령으로 옮기면 된다. |
| ④ 본문·캡션 수정 | 바뀐 수치에 맞게 문장 고쳐 쓰기 | **보조 자동화만 가능** | Codex가 문체 지침에 맞춰 초안을 쓰고 ③이 수치를 검증할 수 있다. 순위·추세 해석 변화, 분쟁·난민처럼 민감한 주제의 표현은 사람이 판단해야 한다. |
| ⑤ 이용 조건·출처 확인 | 라이선스와 인용 문구 재확인 | **사람이 해야 함** | 약관 해석이 필요하다. |
| ⑥ 공개 | 병합·푸시·배포 | **사람 승인 후 자동** | 학년 중간에 수치가 바뀌면 수업 중 학생 결과 파일과 교사 안내가 서로 어긋난다. |

**결론:** ①~③은 자동화할 수 있다. ④~⑥은 자동화가 만든 변경안을 사람이 검토하고 승인하는 구조가 적절하다. 자료가 바뀌었다고 본문까지 자동으로 바꾸어 공개하는 방식은 권하지 않는다. 숫자는 맞아도 해석 문장이 틀릴 수 있기 때문이다.

## 5. 권장 운영 방식 [판단]

### 5-1. 갱신 주기

- **정기 갱신은 연 1회, 학기 시작 전(12~2월)에 한다.**
  - 이 시기에는 WDI·FAOSTAT·UNHCR·UCDP·Global Carbon Budget의 전년도 발표가 대부분 끝나 있다.
  - 한 학년 동안 같은 수치를 유지하면 수업 자료와 교사 안내가 어긋나지 않는다.
- **수시 점검은 2-2의 사건성 자료만 대상으로 한다.**
  - 예: EU 회원국 변화, 대피 장소 지정 변경, 큰 재난.
- **감지는 매월 자동으로 돌린다.** 새 자료가 생겼다는 사실만 알린다.

### 5-2. 갱신 절차(제안)

1. 감지 보고서를 확인하고 이번에 올릴 자료를 정한다.
2. 갱신용 브랜치를 만들고, 연도 상수와 판 URL을 바꾼 뒤 스크립트를 다시 실행한다.
3. `npm run check:book`, `npm test`, 숫자 대조를 실행해 맞지 않게 된 문장 목록을 얻는다.
4. 목록을 Codex에 넘겨 문체 지침(`content/textbook-style.md`)에 맞는 수정 초안을 받는다. 숫자 대조를 다시 통과해야 한다.
5. 연구자가 해석 변화, 민감한 표현, 이용 조건을 검토하고 manifest·출처 기록을 갱신한다.
6. 병합하고 푸시한다. 갱신 기록은 `coordination/`에 남긴다.

### 5-3. 자동화를 위해 먼저 고칠 것

| 순서 | 작업 | 효과 |
| --- | --- | --- |
| 1 | 숫자 대조 스크립트를 저장소의 `npm run check:numbers`로 옮긴다. | 갱신 뒤 고쳐야 할 문장을 자동으로 찾는다. 지금도 문체 수정 검증에 쓰는 도구라 바로 옮길 수 있다. |
| 2 | 출처별 최신 연도 감지 스크립트를 만든다(`scripts/data/freshness.py`). | ① 단계를 자동화한다. 결과는 "현재 연도 / 원천 최신 연도 / 판 번호" 표로 낸다. |
| 3 | 흩어진 연도·판 상수를 한 설정 파일(예: `content/data-years.yaml`)로 모은다. | 연 1회 갱신 때 33개 스크립트를 일일이 열지 않아도 된다. |
| 4 | 캡션의 연도를 자료 파일의 `year`에서 읽어 표시하도록 바꾼다(선택). | 캡션·대체 텍스트 수정 부담이 줄어든다. 파일 이름의 연도도 새 자료부터 뺄 수 있다. |
| 5 | GitHub Actions 정기 실행으로 감지 보고서를 이슈로 남긴다(선택). | 연구자 컴퓨터가 꺼져 있어도 감지가 돈다. 자료 재수집과 본문 수정은 하지 않는다. |

### 5-4. 자동화하지 않을 것

- **Pew 종교 자료와 사가르마타 방문객 자료(PDF 표 판독):** 새 보고서가 나오면 사람이 표를 확인하고 옮긴다.
- **EU 회원국·UNESCO 등재 사실(손으로 옮긴 값):** 사건이 있을 때만 수정한다.
- **농림축산식품부 자급률:** 게시물 주소가 바뀌므로 해마다 새 게시물을 찾아 첨부 파일 URL을 갱신한다.
- **이용 조건 재확인과 공개 승인.**

## 6. 갱신 전 확인 목록

- [ ] 원 사이트에서 새 판·새 연도가 실제로 공개되었는가. 잠정치(provisional)는 아닌가. 세계 합계가 잠정치일 때는 직전 완결 연도를 쓴다(01-01 시계열의 `maxYear: 2024` 사례).
- [ ] 지도 자료의 유효 국가 수가 충분한가. 01-01은 80% 이상을 기준으로 삼았다.
- [ ] 결측값을 0으로 바꾸거나 보간하지 않았는가.
- [ ] 본문·캡션·대체 텍스트·manifest 요약·교사 안내의 수치가 새 자료와 일치하는가.
- [ ] 순위나 추세가 뒤집혀 해석 문장을 바꿔야 하는 곳은 없는가.
- [ ] 이용 조건이 바뀌지 않았는가. 출처 표기 문구가 최신인가.
- [ ] `npm run check:book`, `npm test`, `npm run build`가 모두 통과하는가.
