## 1. 의도와 이유

고등학교 선택 과목 「세계시민과 지리」의 디지털 교과서를 **질문 기반 탐구 수업 설계 이론에 근거해** 처음부터 다시 구성한다. v1은 4개 대단원·13개 중단원·41개 절과 13개 성취기준 모듈을 갖췄지만 실제 사용 장면에서 다음 문제가 있었다.

- 화면이 책보다 웹앱에 가깝다. 8~11px 글씨가 100곳 이상, 절마다 반복되는 라벨·배지·안내문, 오른쪽에 늘 따라붙는 카드 4개가 학습 내용을 가린다.
- 절 본문이 2문단 안팎이라 교과서로서 내용이 얇고, 이미지가 하나도 없으며, 지도·그래프는 모식 자료다.
- 절 사이 연결이 이전·다음 링크뿐이고, QFT는 성취기준 모듈 화면에 따로 떨어져 있다(1단원 9개 실습은 절마다 QFT 단계를 둔다).

v2의 목표는 **학생이 수업 시간에 각자 기기로 읽는 책**이다. 학생은 중단원 첫머리에서 질문을 만들고, 절을 읽고 실제 자료를 다루며 그 질문의 근거를 모으고, 중단원 끝에서 설명하고 다듬고 새 사례에 적용한다. 교사는 학생 결과 파일을 모아 보고 피드백한다.

## 2. 목표·비목표·실패 조건

**목표**
1. 교과서처럼 읽히는 펼침면 지면: 왼쪽 학습 내용, 오른쪽 자료·활동. [결정]
2. 중단원 단위 QFT와 점진적 탐구로 13개 중단원 각각이 하나의 탐구 단위가 되고, 절은 학생 질문의 근거를 제공한다. [결정]
3. 지도·통계는 실제 공개 자료로 웹에서 그린다. [결정]
4. 학생 결과를 파일로 제출하고 교사가 브라우저에서 모아 본다. [결정]
5. 개념 ID로 절·중단원·대단원을 엮어 질문·근거가 다음 학습으로 이어진다. [결정: 유기적 연계 / 제안: 개념 ID 방식]

**비목표(v2에서 하지 않음)**
- 사이트 안의 생성형 AI 호출, AI 코치, 자동 채점. 외부 Gemini·Suno 선택 활동은 v1 결정대로 남되, 학생의 독립 질문 산출 뒤에만 연다.
- 계정·서버·실시간 공유. 학습 로그(스크롤 위치, 체류 시간) 수집.
- 교과서 원문 문장·지면·이미지의 사용. 구조·순서·분량·지면 감각만 따른다. [결정]
- 교실 적용, 학생·교사 모집, 연구 자료 수집.

**실패 조건(돌아가도 실패로 보는 경우)**
- 장식 문구와 작은 글씨가 다시 늘어 본문보다 눈에 띈다.
- 학생의 첫 질문 전에 예시 질문(교사·AI)이 보인다.
- 사실과 다른 지도 경계·지명·통계, 출처 없는 수치, 실제 자료처럼 보이는 모식 자료.
- 학생 질문과 절 내용이 따로 놀아 QFT가 형식적 절차로만 남는다.
- 수업 활동용 전이 과제와 연구 측정용 동형 과제가 섞인다.

## 3. 교수학습 설계의 근거

프로젝트에 이미 정리된 근거를 사용한다. 새 문헌은 연구 폴더의 검증 절차를 거쳐 추가한다.

| 근거 | 교과서에서 맡는 역할 |
| --- | --- |
| Question Formulation Technique(질문 형성 기법, QFT), Right Question Institute 공식 자료 | 중단원 여는 펼침면의 질문 절차: 질문 초점 → 규칙 안내 → 질문 만들기 → 닫힌/열린 질문 분류·바꾸기 → 우선순위 질문 선택 → 다음 단계 계획 → 성찰 |
| Progressive Inquiry(점진적 탐구) | 중단원 전체를 하나의 탐구로 조직: 질문 → 작업 이론 → 자료 탐색 → 질문 심화 → 설명. 절은 "자료 탐색" 단계의 거점 |
| Knowledge Building(지식 구축) | 질문과 설명을 고쳐 쓰는 과정을 남기고, 교사 모아보기에서 학급의 질문 지형을 공유하는 근거 |
| 개념기반탐구 | 성취기준 → 핵심 개념 → 절 → 전이 과제를 개념 ID로 연결 |
| Pedaste et al. (2015) 탐구 주기, Lazonder & Harmsen (2016) 안내된 탐구 | 학생 주도 질문에 교사 안내·비계를 결합하는 근거. 절마다 자료 조작에 안내 단계를 둔다 |

이 결합은 효과가 검증된 통합 모형이 아니라 본 연구의 설계 원리 후보다. 교과서 화면에 효과를 주장하는 문구를 넣지 않는다.

## 4. 교과서 구조

- 4개 대단원, 13개 중단원(=13개 성취기준), 41개 절. 이름과 순서는 v1 `bookIndex.js`를 따른다. [결정]
- 수업 장면은 학생 1인 1기기, 교사 진행이다. [결정]

### 4.1 중단원 하나의 흐름 [결정 + 제안]

```
[중단원 여는 펼침면]
 왼쪽: 중단원 소개, 성취기준을 학생 말로 풀어 쓴 목표, 큰 도입 삽화
 오른쪽: 질문 초점(실제 지도·사진·그래프, 질문형 문장 없음)
        → QFT: 질문 만들기 → 닫힌/열린 바꾸기 → 중심 질문 3개 선택 → 개념 태그 붙이기

[절 펼침면 × 3~4]      (스크롤 연동)
 왼쪽: 절 제목·학습 목표, 본문 4~6문단, 핵심 낱말
 오른쪽(고정): 문단마다 대응하는 자료 상태 → 본문 끝에서 탐구 활동으로 전환
        + "내 질문 중 이 절과 관련된 것" 표시 → 근거 붙이기(자료 단계 ID 연결)

[중단원 닫는 펼침면]
 왼쪽: 정리, 다음 중단원으로 이어지는 연결 문장
 오른쪽: 내 질문에 대한 설명 쓰기(근거 연결) → 질문 다시 다듬기 → 새 사례에 적용(전이)
        → 결과 파일 내보내기
```

- 절 수: 중단원마다 v1의 절 구성을 유지한다(3~4개).
- **QFT 7단계의 배치** [제안]
  - 여는 펼침면: 규칙 안내(한 줄, 교사가 말로 진행), 질문 만들기, 닫힌/열린 분류·바꾸기, 우선순위 질문 3개 선택, 다음 단계 계획(개념 태그 + "어느 자료에서 찾을지" 한 줄). 한 화면을 넘으면 오른쪽 쪽 안에서 단계별로 넘긴다.
  - 닫는 펼침면: 성찰("질문이 어떻게 바뀌었나, 무엇을 배웠나").
  - 이렇게 7단계를 모두 유지하므로 QFT 절차를 생략했다는 연구상 문제가 생기지 않는다.
- **절의 탐구 활동 형태** [제안]
  - 재사용 활동 템플릿 소수를 만들고 절마다 설정 파일로 고른다. 후보는 지도 레이어 비교, 시계열·국가 비교 그래프 읽기, 근거 고르기·분류, 의사결정 매트릭스, 연표다.
  - 템플릿으로 표현할 수 없는 활동만 맞춤 엔진으로 만든다(1단원 기존 엔진 포함).
  - 템플릿과 맞춤 엔진은 Claude가 구현하고, 절별 설정은 Codex가 쓴다.
- 1단원의 기존 9개 절별 실습(`src/lesson-modules/unit-01/`)은 절의 "탐구 활동" 엔진으로 옮긴다. 절마다 있던 QFT 단계는 중단원 여는 펼침면으로 올리고, 절에서는 질문을 다시 불러와 근거를 붙이는 역할만 한다. [제안]

### 4.2 분량 [제안]

- 절 본문: 4~6문단, 10~15분 안에 읽는 분량. 문단 하나에 오른쪽 자료 상태 하나.
- 절당 자료 상태: 2~4단계, 실제 자료 1~2종.
- 중단원 여는·닫는 펼침면은 각각 한 화면 분량이다.

### 4.3 유기적 연계 [제안]

- **개념 ID**: 성취기준·절·자료 단계마다 개념 ID(예: `interdependence`, `scale`)를 붙인다. 핵심 낱말도 문자열이 아닌 ID로 관리한다.
  - 골격 단계에서 13개 중단원 전체의 개념 사전 초안을 만든다. 근거는 2022 개정 교육과정 「세계시민과 지리」의 핵심 아이디어·내용 요소와 연구 폴더의 성취기준 매핑(`method/achievement-standard-platform-map-2026-11-11.md`)이다. 연구자는 01-01 검토 때 함께 확인한다. [제안]
  - 한 번 공개한 ID는 바꾸거나 지우지 않는다. 합치거나 이름을 바꿀 때는 별칭 표를 두어, 이미 내보낸 학생 파일도 교사 모아보기에서 읽히게 한다. [제안]
- **질문 이월**: 학생이 중심 질문에 개념 태그를 붙이면, 같은 개념을 다루는 절의 오른쪽 쪽에 그 질문이 떠오른다. 다음 중단원 여는 펼침면에는 "지난 중단원에서 남은 질문"을 한 줄로 보여 준다. 단, 이 줄은 학생이 새 질문을 만든 **뒤에** 열린다. QFT의 독립 질문 원칙을 지키기 위해서다.
- **근거 이월**: 근거는 `(절 ID, 자료 단계 ID, 학생 메모)` 형태로 저장해 닫는 펼침면의 설명 쓰기에서 고를 수 있게 한다.
- **사례 재방문**: v1의 7개 실제 사례는 여러 중단원에서 다른 관점으로 다시 나오고, 처음 나온 곳으로 링크한다.
- **책 전체 개념 지도**: 목차 화면에 대단원·중단원과 개념 ID의 관계를 Cytoscape로 보여 준다. 장식이 아니라 "이 개념은 어디서 또 나오나"를 찾는 길잡이로 쓴다.

## 5. 지면과 화면 원칙

- **펼침면**: 기준 폭 1024px 이상에서 좌우 두 쪽. 그보다 좁으면 위아래로 접고, 순서는 글 → 자료 → 활동으로 유지한다. [결정: 펼침면 / 제안: 기준 폭]
- **스크롤 연동**: 오른쪽 쪽은 고정된 채 내용만 바뀐다. 구현은 브라우저 `IntersectionObserver` 또는 오픈소스 스크롤 라이브러리(후보: Scrollama, 도입 전 라이선스·버전 확인)로 한다. [결정: 스크롤 연동 / 빌더: 라이브러리 선택]
  - 학생이 자료를 직접 조작하면 그 상태를 고정하고, "본문과 다시 맞추기" 버튼으로 연동을 되돌린다.
  - 활동·입력 구간에서는 연동을 끈다.
  - `prefers-reduced-motion`에서는 전환 효과를 없앤다. 각 자료 상태에는 텍스트 대체 설명을 둔다.
- **글자와 장식** [결정: 작은 글씨 제거 / 제안: 수치]
  - 본문 17~18px, 행간 1.75 이상. 화면의 어떤 글자도 14px 미만으로 쓰지 않는다.
  - 라벨·배지·눈썹 제목(eyebrow)은 쓰지 않는다. 쪽 번호와 절 번호만 둔다.
  - 반복 안내문("서버에 전송되지 않습니다" 등)과 연구상 면책("모식 자료", "비검증 피드백")은 지우지 않고 **도움말 한 곳**에 모은다. 단, 모식 자료가 화면에 있으면 그 자료의 캡션에는 반드시 밝힌다.
  - 한 화면에서 주요 행동은 하나다.
- **교사용 안내**: 학생 페이지에 토글을 두지 않고, 별도 교사용 경로(교사용 모아보기와 같은 곳)에 중단원별로 둔다. 발문, 예상 질문, 시간 배분, 오개념을 담는다. 학생 화면에서 교사용 경로로 가는 링크는 두지 않는다. 접근 통제는 하지 않지만(서버 없음), 학생이 첫 질문 전에 예상 질문을 우연히 보는 일은 막는다. [제안: 예상 질문이 QFT 독립 질문 원칙과 충돌하지 않게]
- **디자인 토큰**: 종이색 배경, 명조 계열 본문, 고딕 계열 캡션·활동, 대단원별 강조색 하나. 다크 모드는 v2에서 선택 사항이다. [빌더]

## 6. 실제 자료와 시각화

- 지도·통계는 **공개 라이선스의 실제 자료**만 쓴다. [결정]
- 처리 경로: 원자료 → Python 가공 스크립트(Colab 또는 로컬) → 정적 파일(GeoJSON/CSV/JSON, 필요하면 PMTiles) → `public/data/<중단원>/`. 무거운 계산은 브라우저에서 하지 않는다. [제안, v1 결정과 일치]
- 자료마다 `data/manifest`에 출처 기관, URL, 받은 날짜, 라이선스, 가공 스크립트 경로, 단위·기준 연도를 기록한다. 캡션에는 출처와 기준 연도를 표시한다.
- 지도 경계: 분쟁 지역(예: 키프로스, 골란)은 국제기구(UN 등) 표기 원칙을 따르고, 캡션에 "경계는 실제 영유권에 대한 판단을 뜻하지 않음"을 밝힌다. 배경 지도의 타일 공급원은 이용 조건을 확인해 정한다. [빌더, 조건부]
- 라이브러리: MapLibre GL JS, ECharts, Cytoscape(이미 사용 중)를 유지한다. 새 라이브러리는 오픈소스 라이선스와 유지 상태를 확인한 뒤 추가하고 목록에 기록한다.
- 모식 자료는 실제 자료를 구할 수 없는 경우에만 쓰고, 캡션에 모식임을 밝힌다.
- **수치는 실제, 상황은 허구 허용** [결정]
  - 화면에 지도·그래프·표로 보여 주는 수치와 위치는 실제 자료다.
  - 역할극·청문회·의사결정 장면 같은 상황 설정은 허구를 허용하되, 활동 첫머리에 "가상 상황"이라고 밝힌다. 허구 상황 안에서 쓰는 수치도 실제 자료에서 가져온다.
  - 01-01 적용: 가상 티셔츠 공급망(`lesson-01-01-01`)은 실제 무역 통계 기반 흐름으로, 가상 해안 마을(`-02`)은 실제 사례 지역으로 바꾼다. 가상 학교 공동구매 청문회(`-03`)는 가상 상황으로 밝히고 남긴다. 1단원 나머지 실습(예: `LivingRegionLab`의 가상 통근 자료)도 확산 단계에서 같은 원칙으로 고친다.

## 7. 이미지

- **범위**: 대단원·중단원 도입 삽화와 개념 설명 삽화(절당 0~1장)만 둔다. 지도, 통계, 실제 사례 장면(특히 분쟁·재난 지역)은 AI 이미지로 만들지 않는다. [결정]
- **제작**: Codex CLI의 이미지 생성 기능으로 **제작 시점에만** 만들고, 결과를 정적 파일(`public/images/<중단원>/`, WebP)로 저장한다. 사이트는 실행 중에 AI를 호출하지 않는다. [결정]
- **가능 여부**: Codex CLI 0.172.0(`gpt-6-luna`, max)에서 `image_generation` 기능이 켜져 있음을 확인했다(2026-11-26). 실제 이미지 산출은 골격 단계에서 1장을 시험 생성해 확인한다. 생성이 안 되거나 품질이 기준에 못 미치면 삽화 없이 진행하고, 개념 삽화는 코드로 그린 SVG 도식으로 대신한다. 시범 중단원의 완료 기준에서 삽화는 필수가 아니다. [제안]
- **일관성**: 삽화 양식 지침(화풍, 색 범위, 사람 묘사 원칙, 이미지 속 글자 금지)을 한 파일로 정해 모든 프롬프트에 붙인다. [제안]
- **기록과 검수**: 이미지마다 프롬프트, 생성 날짜, 모델, 사용 위치, 대체 텍스트를 `image-provenance` 기록에 남긴다. 검수 항목은 지명·국기·경계 묘사 오류, 글자 깨짐, 실존 인물·상표, 고정관념적 묘사다. 통과하지 못하면 다시 만들거나 뺀다.

## 8. 학생 결과 파일과 교사용 모아보기

- **학생 기록**: 브라우저 localStorage에 중단원별로 저장한다. v1 기록 구조는 이전 버전으로 읽어 들여 손실 없이 옮긴다. [제안]
- **결과 파일**: 중단원 닫는 펼침면에서 내보낸다. JSON 형식이고, 확장자와 스키마 버전을 고정한다. [결정: 파일 제출 / 빌더: 세부 스키마]
  - 내용: 중단원 ID, 학생 표시명(학급 번호나 별칭, 실명 입력은 권하지 않음), 만든 질문 전부(원 질문·바꾼 질문·선택 여부·개념 태그), 근거 연결, 설명, 다듬은 질문, 전이 응답, 단계별 시각.
  - 학생은 이 파일을 학교 LMS(예: 클래스룸)에 제출한다. 사이트가 직접 업로드하지 않는다.
- **교사용 모아보기**: 별도 페이지에서 여러 결과 파일을 끌어다 놓으면 브라우저 안에서만 읽는다.
  - 보기: 학생별 질문 흐름, 학급 전체 질문의 닫힌/열린 비율과 개념 태그 분포, 근거 없는 설명 표시, 중심 질문 목록.
  - 출력: 인쇄용 요약.
  - 파일은 어디에도 업로드·저장하지 않는다. 페이지를 닫으면 사라진다.
- **연구 자료와의 경계**: 같은 파일을 연구 자료로 쓰는 것은 윤리 승인과 동의 절차를 거친 뒤에만 가능하다. 연구 측정용 동형 과제는 이 교과서의 전이 활동과 별도 화면으로 둔다(v2 범위 밖).

## 9. 콘텐츠 형식

- 중단원마다 폴더 하나를 둔다. 폴더에는 중단원 파일(여는·닫는 펼침면, 성취기준, 개념 ID, 질문 초점, 교사용 안내)과 절 파일들(본문 문단, 문단별 자료 단계 ID, 핵심 낱말 ID, 활동, 출처 ID)이 들어간다. 사람이 읽고 고치기 쉽게 **마크다운 + 머리말(YAML)**로 쓰고, 빌드 시 읽어 들인다. [제안: Codex가 쓰고 사람이 검토하기 쉬움 / 빌더: 파서 선택]
- v1의 성취기준 모듈 파일(`src/modules/`)과 단원 파일(`src/content/units/`)로 이원화된 구조는 이 형식으로 합친다.
- **구조 검사 스크립트**(빌드 전에 실행):
  - 중단원 13개·절 41개 존재
  - 절마다 필수 블록과 본문 문단 4~6개
  - 문단–자료 단계 대응
  - 개념 ID가 사전에 있음
  - 출처 ID 실재, 자료 manifest 항목 실재
  - 이미지 provenance 기록 실재
  - 질문 초점에 물음표 없음
  - 화면용 CSS에 14px 미만 글자 크기 없음

## 11. 진행 단계

1. **골격**: 새 브랜치(제안: `redesign/v2`, `platform/web-prototype` 저장소)를 만든다. 콘텐츠 형식·로더, 펼침면·스크롤 연동 화면, 디자인 토큰, 구조 검사를 갖추고 지도·그래프·QFT·저장 부품을 이식한다. `main`은 연구자 승인 전까지 건드리지 않는다.
2. **시범 중단원 01-01 세계화와 세계시민(3개 절)**: 본문, 실제 자료 2~3종, 삽화, 중단원 QFT, 절별 근거 붙이기, 닫는 펼침면, 결과 파일, 교사용 모아보기를 완성한다.
3. **연구자 검토**: 01-01을 실제 기기(태블릿·크롬북 폭)에서 확인하고 틀을 고친다.
4. **확산**: 나머지 12개 중단원을 중단원 단위로 Codex에 맡기고, 하나씩 검수·통합한다. 대단원 1(나머지 2개 중단원)부터 진행한다.
5. **전체 점검**: 구조 검사, 접근성(키보드, 대체 텍스트, 대비), 출처·자료·이미지 기록, 빌드 결과를 점검한다. 푸시는 연구자가 요청할 때만 한다.

## 12. 작업 분담과 Codex 운영

- **Claude(조정·개발 총괄)**: 콘텐츠 형식과 화면 부품 설계, 핵심 컴포넌트 구현, Codex 작업 지시서 작성, 결과의 사실·출처·코드 검수, 통합, 연구 폴더 기록.
- **Codex CLI(`gpt-6-luna`, 추론 강도 max, `.codex/config.toml` 기준)**: 중단원별 본문·교사용 안내 초안, 자료 가공 스크립트와 정적 자료 산출, 삽화 생성, 반복적인 형식 변환, 구조 검사 결과 정리.
- **운영 규칙**
  - 지시서는 `STUDY_ROOT/coordination/requests/`에, 결과 보고는 `coordination/handoffs/`에 `research/templates/agent-handoff.md` 형식으로 남긴다.
  - Codex는 `codex exec`로 비대화형 실행하고, 쓰기 범위를 해당 중단원 폴더·자료·이미지 폴더로 제한한다(`--sandbox workspace-write`).
  - 커밋·푸시는 하지 않는다. Claude가 변경분을 검토한 뒤 통합한다.
  - 호출 한 번의 고정 비용이 크므로(시험 호출 약 1.6만 토큰), 작업은 중단원 단위로 묶어 맡긴다.
  - 같은 파일을 두 작업자가 동시에 쓰지 않는다.
  - Codex가 쓴 사실 진술·수치·출처는 Claude가 원 출처와 대조해 검증한다. 확인되지 않은 것은 본문에서 빼거나 표시한다.

## 13. 제약

- 공개 사이트(일반 공개 목표)에는 교과서 원문·이미지를 넣지 않는다.
- 사이트 실행 중 생성형 AI 호출 0회.
- 미성년자 개인정보를 수집하지 않는다. 결과 파일은 학생이 직접 제출한다.
- React 19 + Vite 기반을 유지한다. 정적 호스팅이 가능해야 한다.
- 모든 연구 기록은 연구 폴더 안에 둔다. 원자료 대용량 파일은 복사하지 않고 위치만 기록한다(가공 산출물만 저장소에 둔다).
