# 소절 활동에 Thinking Routines 넣기 — 설계

작성: 2026-11-27 · 상태: 연구자 승인 대기
관련 기록: `STUDY_ROOT/method/thinking-routines-lesson-map-2026-11-27.md`(카테고리 확인 기록과 41개 소절 대응표)

## 1. 왜 하나(연구자 결정)

- 연구자는 Harvard Project Zero(PZ)의 Thinking Routines를 수업에 들이자고 제안했다.
- 검토 뒤 연구자 결정은 이렇다.
  - **중단원의 QFT(질문 만들기 → 다듬기)는 유지한다.**
  - **소절 활동에 Thinking Routines를 넣는다.**
  - 구현은 **1안**으로 한다. 공통 「루틴 카드」를 생각 열기, 탐구하기, 내 질문과 이 절 세 곳에 두고, 기존 활동은 유지한다.
- 목표: 학생이 자료를 보고 생각을 꺼내고(생각 열기), 관점·쟁점·세계와의 연결을 따지고(탐구하기), 생각의 변화를 정리하는(마무리) 사고 과정을 소절마다 눈에 보이게 한다. QFT 질문 흐름과도 이어지게 한다.

## 2. 목표·비목표·피해야 할 것

**목표**
- 41개 소절 모두에 생각 열기 루틴 1개, 탐구하기 루틴 1개, 마무리 루틴 1개를 둔다.
  - 마무리의 기본값은 I Used to Think… Now I Think…다.
- 루틴 응답은 학생 기기에 저장되고, 결과 파일로 내보내지고, 교사 모아보기에서 보인다.
- See, Think, Wonder의 「궁금한 것」은 버튼 하나로 「학습 중 생긴 질문」(QFT 질문 목록)에 넣을 수 있다.

**비목표**
- QFT 단계와 여는 쪽·마무리 쪽은 바꾸지 않는다.
- 기존 활동 틀 4종과 41개 활동 내용은 그대로 둔다.
- 질문을 만드는 PZ 루틴(Creative Questions, Creative Question Starts)은 넣지 않는다. QFT와 겹친다.
- 모둠 협업, 실시간 공유 기능은 만들지 않는다. 지금처럼 개인 기기 기록만 다룬다.

**피해야 할 것**
- PZ 설명문을 번역하거나 고쳐 싣는 것
  - 개별 루틴 페이지는 CC BY-NC-ND 4.0이고, Global Thinking 묶음은 CC BY-NC 4.0이다.
  - 학생용 안내문은 우리말로 새로 쓴다. 루틴 이름과 출처는 밝힌다.
- 학생 부담이 커지는 것
  - 루틴 칸은 한두 문장 분량으로 한다.
  - 루틴 응답은 「다음 단계」를 막는 필수 입력으로 만들지 않는다.
- 작은 장식 글씨
  - 출처·이용 조건은 루틴 카드마다 붙이지 않는다. 도움말 쪽 한 곳에 모은다.

## 3. 접근 방식

| 안 | 내용 | 결정 |
| --- | --- | --- |
| **1안: 공통 루틴 카드 × 세 위치** | 루틴 사전(우리말 안내) + 절별 지정(루틴 id와 절 맞춤 안내 한두 문장). 카드 부품 하나로 41개 절에 붙인다. 기존 활동 유지 | **연구자 선택** |
| 2안: 탐구하기 활동을 루틴 모양으로 재구성 | 루틴별 전용 활동 틀 15개 안팎 신설, 41개 활동 재작성 | 개발량 최대, 검수한 활동 폐기 → 제외 |
| 3안: 생각 열기·정리에만 루틴 | 가장 가볍다. 그러나 관점·쟁점·전역적 사고 루틴이 빠진다. | 제외 |

## 4. 학생 화면(1안)

```
[생각 열기] 기존 opener 문장
  ┌ 생각 루틴 · See, Think, Wonder(보고·생각하고·궁금해하기) ┐
  │ 절 맞춤 안내 한 문장(예: 오른쪽 첫 지도를 보고 적어 보자)       │
  │ 본 것 [   ]  생각한 것 [   ]  궁금한 것 [   ] [질문 목록에 넣기] │
  └────────────────────────────────────┘
…소주제 본문…
━━ 탐구하기 ━━
  ① 생각 루틴 · Step In, Step Out, Step Back  (칸 2–3개)
  ② 기존 활동(가상 협의회 등)
━━ 핵심 정리 ━━
━━ 내 질문과 이 절 ━━
  생각 루틴 · I Used to Think… Now I Think…  (칸 2개)
  (기존) 근거 붙이기 · 이 절을 마치며 새로 생긴 질문
```

- **카드 머리말:** 「생각 루틴 · 영어 이름(우리말 풀이)」. 영어 이름은 첫 표기 규칙(English(한글 풀이))을 따른다.
- **칸:** 루틴의 단계 수만큼 둔다(2–4개). 칸마다 우리말 단계 이름과 짧은 안내를 붙인다.
- **질문 보내기:** 단계에 `toQuestion: true`가 있으면(예: 궁금한 것) 「질문 목록에 넣기」 버튼이 붙는다. 누르면 그 내용이 `newQuestion(text, { fromLessonId })`로 QFT 질문 목록에 들어간다. 기존 「새로 생긴 질문」과 같은 경로다.
- **좁은 화면:** 칸이 세로로 쌓인다.
- **글자 크기:** 14px 이상을 지킨다.

## 5. 콘텐츠 형식(설계자 판단)

### 5-1. 루틴 사전 `content/routines.yaml`

```yaml
source:
  title: Project Zero Thinking Routines
  organization: Project Zero, Harvard Graduate School of Education
  url: https://pz.harvard.edu/thinking-routines
  license: 루틴 페이지 CC BY-NC-ND 4.0 / Global Thinking 묶음 CC BY-NC 4.0
  note: 학생용 안내문은 이 교과서가 새로 쓴 것이며 PZ 원문의 번역이 아니다.
routines:
  see-think-wonder:
    name: See, Think, Wonder
    nameKo: 보고·생각하고·궁금해하기
    category: [core, introducing_and_exploring_ideas]
    url: https://pz.harvard.edu/resources/see-think-wonder
    steps:
      - { id: see, label: 본 것, hint: 자료에서 눈에 띄는 것을 그대로 적는다 }
      - { id: think, label: 생각한 것, hint: 왜 그렇게 보이는지 생각을 적는다 }
      - { id: wonder, label: 궁금한 것, hint: 더 알고 싶은 점을 적는다, toQuestion: true }
```

- 대응표에 쓰인 루틴 약 25개를 이 형식으로 둔다.
- 안내문(`label`, `hint`)은 우리말로 새로 쓴다.

### 5-2. 절별 지정(lesson-N.md 머리말)

```yaml
routines:
  opener:  { id: see-think-wonder, prompt: 오른쪽 첫 지도에서 무역 비중이 높은 나라를 보고 적어 보자. }
  inquiry: { id: three-whys, prompt: 세계화가 나·우리 지역·세계에 왜 중요한지 세 규모로 정리하자. }
  closing: { id: used-to-think }   # 생략하면 used-to-think
```

### 5-3. 구조 검사(`check:book`) 규칙

module 형식 절은 다음을 지켜야 한다.
- `routines.opener`와 `routines.inquiry`가 있어야 한다.
- 모든 id가 루틴 사전에 있어야 한다.
- `prompt`는 비어 있지 않아야 한다(closing 제외).
- 루틴 사전의 각 루틴은 단계가 2–4개여야 하고, `toQuestion`은 루틴당 1개 이하여야 한다.

## 6. 학생 기록·결과 파일·교사 모아보기(설계자 판단)

- **학생 기록**
  - v4 기록에 `routineState: { [lessonId]: { opener: {stepId: text}, inquiry: {...}, closing: {...} } }`를 더한다.
  - 정규화 때 없으면 `{}`로 둔다. 저장 형식 버전은 v4 그대로다.
- **결과 파일**
  - 선택 필드 `routineResponses`(= routineState)를 더한다.
  - 지금 빠져 있는 `activityState`(탐구하기 활동 응답)도 함께 더한다.
  - `schemaVersion`은 1을 유지하고, 형태 검사는 두 필드를 객체 또는 없음으로 허용한다. 옛 파일도 그대로 읽힌다.
- **교사 모아보기:** 학생별 흐름에 「생각 루틴」 칸을 더한다. 절마다 세 루틴의 응답을 보여 준다.
  - `activityState`는 결과 파일에 담기만 한다. 교사 화면에 활동 응답을 보여 주는 일은 이번 범위가 아니다. 활동 틀 4종마다 따로 읽기 화면이 필요하기 때문이다.
- **연구 자료와의 관계(설계자 판단)**
  - 결과 파일은 수업용 기록이다. 교사가 모아 수업 피드백에 쓴다.
  - 지금도 질문·설명·돌아보기 같은 자유 서술이 들어 있다. 루틴 응답을 더해도 자료의 성격은 같다.
  - 아직 연구 참여자 모집이나 연구용 수집은 하지 않는다(학교 적용 전).
  - 결과 파일을 연구 자료로 쓰려면 별도의 연구 계획, 동의 절차, 기관 심의를 먼저 거쳐야 한다. 이 점을 `brief.md`에 기록한다.
- **한 자리에 두 루틴을 쓰던 대응표 항목**
  - 해당 절: 04-03-1(Claim, Support, Question + Facts or Fiction), 04-03-3(정리 Headlines)
  - 한 자리에는 루틴 하나만 둔다. 04-03-1은 Claim, Support, Question, 04-03-3의 정리는 I Used to Think…를 쓴다.
  - 바꾼 내역은 대응표에 기록한다.
- **도움말 쪽:** 「생각 루틴의 출처」 구역을 둔다. 내용은 PZ 출처, 이용 조건, 루틴별 원 페이지 링크, 안내문을 새로 썼다는 고지다.

## 7. 진행 순서

1. **화면·저장:** 루틴 사전 해석과 검사, 루틴 카드, 세 위치 배치, 저장, 결과 파일, 교사 모아보기, 도움말. 테스트를 먼저 쓴다.
2. **루틴 사전:** 대응표에 쓰인 루틴의 우리말 안내문을 쓴다.
3. **41개 절 지정:** 대응표대로 `routines`를 넣고, 절 맞춤 `prompt`를 쓴다(Codex 초안 → Claude 검수).
4. **연구 기록:** `brief.md`, 문헌 서지(Ritchhart, Church, & Morrison, 2011 등)를 확인해 기록하고, 교사용 안내를 갱신한다.
5. **확인:** 전체 검사, 브라우저 확인, 다른 검토자의 검토. 커밋은 단계별로 한다. 푸시는 연구자 요청이 있을 때만 한다.

## 8. 설계자에게 맡기는 것

- 카드의 시각 디자인(기존 책 디자인과 맞춤)
- 루틴별 우리말 단계 이름과 안내문 문구(5-1 원칙 안에서)
- 대응표의 일부 루틴 교체: 절 내용과 더 잘 맞는 루틴이 있으면 바꾸고, 바꾼 내역을 기록한다.
